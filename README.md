# speedtest

CLI-утилита для замера скорости скачивания по HTTP. Качает файл N раз,
считает среднее время, объём и скорость в МБ/с и Мбит/с.

## Быстрый запуск

Скрипт сам создаст окружение, поставит зависимости и запустит — вручную
ничего устанавливать не нужно.

Windows (PowerShell):

```powershell
.\run.bat "https://speed.cloudflare.com/__down?bytes=50000000" -n 10
```

В cmd.exe можно без `.\`:

```bat
run.bat "https://speed.cloudflare.com/__down?bytes=50000000" -n 10
```

Linux/macOS:

```bash
./run.sh "https://speed.cloudflare.com/__down?bytes=50000000" -n 10
```

Либо напрямую Python (любая ОС):

```bash
python run.py "https://speed.cloudflare.com/__down?bytes=50000000" -n 10
```

В bash/zsh знак `?` без кавычек раскрывается как wildcard — берите URL в кавычки.

Первый запуск создаёт `.venv` и ставит зависимости; повторные только запускают
замер — окружение ищется рядом с `run.py`, рабочая директория не важна.

## Требования

- Python 3.12+.
- На Windows, если `python` — заглушка Microsoft Store (`where python` ведёт
  в `WindowsApps`), используй `py` вместо `python`.

Только если будешь дорабатывать код. Устанавливает dev-зависимости (линтер
`ruff`, проверку типов `mypy`, тесты `pytest`, `bandit` и т.д.):

python -m venv .venv          # создать изолированное окружение

## Опции

### `-n, --count N` — сколько раз скачать файл

Число замеров (по умолчанию 10). Утилита скачивает файл N раз и по всем замерам
считает среднюю скорость.

**Что даёт:** чем больше замеров, тем надёжнее среднее — один случайный провал
или всплеск не исказит цифру. Минус — дольше идёт.

**Когда менять:** `-n 3` для быстрой прикидки, `-n 10` и больше — для честной цифры.

### `-w, --warmup N` — прогрев перед замерами

Число «холостых» скачиваний до начала замеров (по умолчанию 1). Они не попадают
в статистику.

**Зачем:** первый запрос всегда медленнее — на него приходится установка
соединения (DNS, TCP, TLS) и прогрев кэшей. Без прогрева первый замер
искусственно занижал бы скорость.

### `-t, --timeout S` — сколько ждать ответа

Таймаут одного запроса в секундах (по умолчанию 30). Если сервер не отдал файл
за это время — замер считается ошибкой, а не висит бесконечно.

### `-j, --threads N` — скачивать параллельно

Число одновременных потоков (по умолчанию 1 — последовательно).

**Что даёт:** провайдер часто ограничивает скорость на одно соединение. Один
поток может не выжать всю полосу, а 4–8 потоков — выжмут. В сводке появится две
цифры: «скорость суммарная» (вся полоса) и «скорость на поток».

### `--json PATH` — сохранить результат в файл

Записывает метаданные (URL, время, параметры), сырые замеры и сводку в JSON-файл.
Удобно для скриптов и построения графиков. Несовместим с `--probe-threads`.

### `--phases` — разобрать время соединения

Перед замером делает отдельное пробное подключение и показывает, сколько заняли
этапы: DNS-резолв, TCP-соединение, TLS-рукопожатие, TTFB (время до первого байта).

**Что даёт:** понимание, *почему* медленно. Если DNS — 500 мс, проблема в
DNS-сервере, а не в канале. Если TTFB огромный — сервер долго думает.

### `--probe-threads N` — сравнить 1 поток против N

Короткий прогон в один поток и в N потоков, затем вердикт: ограничена ли скорость
одним соединением или канал уже насыщен.

**Что даёт:** если N потоков заметно быстрее одного — провайдер режет скорость на
соединение (поможет больше потоков). Если разницы нет — канал и так в лимите.

## Примеры

### Базовый замер

```bash
python run.py "https://speed.cloudflare.com/__down?bytes=50000000" -n 10
```

Печатает строку на каждый замер (время, объём, скорость, TTFB, спарклайн), затем сводку:

```text
# 1: 0.958 с | 10.00 МБ | 10.44 МБ/с | TTFB 87 мс | ▃▁▇█
# 2: 0.519 с | 10.00 МБ | 19.28 МБ/с | TTFB 80 мс | ▁▅█
...
Итог
Успешно: 10 из 10 (ошибок: 0)
Среднее время: 0.682 с (min 0.509, max 0.958)
Скорость: 14.67 МБ/с (117.3 Мбит/с)
```

### Параллельный замер

```bash
python run.py "https://speed.cloudflare.com/__down?bytes=50000000" -j 4
```

В сводке появляются две скорости — суммарная и на поток:

```text
Скорость суммарная: 12.05 МБ/с (96.4 Мбит/с)
Скорость на поток: 5.25 МБ/с
```

### Фазы соединения

```bash
python run.py "https://speed.cloudflare.com/__down?bytes=50000000" --phases
```

Показывает, из чего складывается время первого запроса:

```text
DNS              6.3 мс
TCP connect     69.3 мс
TLS handshake   82.9 мс
TTFB           194.4 мс
```

### Сравнение потоков

```bash
python run.py "https://speed.cloudflare.com/__down?bytes=50000000" --probe-threads 4
```

Короткий прогон 1 поток против 4 и вердикт:

```text
1 поток: 10.05 МБ/с
4 потоков: 14.73 МБ/с
Вердикт: канал насыщен одним потоком
```

### Экспорт в JSON

```bash
python run.py "https://speed.cloudflare.com/__down?bytes=50000000" -n 5 --json result.json
```

Записывает метаданные, сырые замеры и сводку в `result.json`.

## Дополнительно

### Кривая скорости

В каждой строке замера — спарклайн скорости по окнам 0.25 с, а в итоге —
пиковая и установившаяся скорость. Видно TCP slow start и просадки, а не
только среднее.

### Фазы соединения

`--phases` измеряет отдельное пробное подключение через stdlib (`socket`/`ssl`),
а НЕ то соединение, которое используется внутри `requests.Session`. Поэтому
цифры фаз могут не совпадать с TTFB основного прогона — это не ошибка, а
намеренно изолированное измерение.

### Сравнение потоков

`--probe-threads 4` делает короткий прогон в 1 поток и в 4 потока, сравнивает
суммарную скорость и выводит вердикт: ограничено ли одно соединение или канал
насыщен одним потоком.

## Как это работает

- **Десятичные единицы.** 1 МБ = 1 000 000 байт, Мбит/с = МБ/с × 8 — как у
  провайдеров, а не 1024 (МиБ).
- **Одна сессия.** `requests.Session` переиспользует TCP/TLS-соединение, так
  что рукопожатие не входит в каждый замер.
- **Сжатие отключено.** `Accept-Encoding: identity`, байты считаются по проводу
  через `r.raw.stream(..., decode_content=False)` — объём не искажается gzip.
- **Кэш обходится.** `Cache-Control: no-cache`.
- **Параллельная скорость.** При `-j N` суммарная скорость считается по
  реальному wall-clock времени всего прогона, а не по сумме времён запросов.
- **Прогрев по потокам.** В `-j N` прогрев идёт в самих потоках (минимум N
  запросов через thread-local сессии), поэтому рукопожатие не входит в первый
  замер каждого потока.

## Ограничения

- Результат зависит от сервера и канала, а не только от вашего интернета.
- Один TCP-поток на быстром канале не выжимает всю скорость — для этого `-j`.
- Для стабильного замера берите файл 10–50 МБ.

Рекомендуемый URL: `https://speed.cloudflare.com/__down?bytes=50000000`.
